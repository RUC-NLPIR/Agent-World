# ClinicalTrials MCP Server — local MCP environment

This backend stores clinical trial search requests made through the MCP server, the resulting study identifiers and cached study payloads retrieved from ClinicalTrials.gov, plus metadata about CSV exports created on disk. Main workflows: execute a search, optionally export selected fields or full studies to CSV, fetch a single study by NCT ID (cached), compute simple statistics over cached/search results, and list/load previously generated CSV files.

Repository: https://github.com/JackKuo666/ClinicalTrials-MCP-Server

## Datastore

- `ct_search_requests.json` — A record of each search invocation (by expression or keyword) including limits, requested fields, and whether a CSV export was requested. (18 rows; fields: ['id', 'search_type', 'search_expr', 'keyword', 'condition', 'max_studies', 'requested_fields', 'save_csv', 'filename', 'results_count', 'error_message', 'status', 'created_at', 'updated_at'])
  - lifecycle `status`: ['queued', 'running', 'succeeded', 'failed']
  - constraint: CHECK (search_type IN ('expression','keyword','statistics'))
  - constraint: CHECK (max_studies BETWEEN 1 AND 1000)
  - constraint: CHECK ((search_type='expression') = (search_expr IS NOT NULL))
  - constraint: CHECK ((search_type='keyword') = (keyword IS NOT NULL))
- `ct_studies.json` — Canonical store of ClinicalTrials.gov studies keyed by NCT ID, including cached full payload for fast repeat reads. (18 rows; fields: ['id', 'nct_id', 'brief_title', 'official_title', 'overall_status', 'conditions', 'study_type', 'start_date', 'completion_date', 'primary_location_countries', 'source_last_updated_at', 'full_payload', 'payload_format', 'cache_status', 'last_fetched_at', 'fetch_error', 'created_at', 'updated_at'])
  - lifecycle `cache_status`: ['partial', 'full', 'stale', 'error']
  - constraint: UNIQUE (nct_id)
  - constraint: CHECK (nct_id ~ '^NCT[0-9]{8}$')
  - constraint: CHECK (payload_format IN ('ctgov_v2_json'))
  - constraint: CHECK (cache_status IN ('partial','full','stale','error'))
- `ct_search_results.json` — Join table associating a search request with the ordered studies returned by that request, plus any per-result summary fields used for display/export. (18 rows; fields: ['id', 'search_request_id', 'study_id', 'rank', 'result_payload', 'created_at', 'updated_at'])
  - lifecycle `status`: []
  - constraint: FOREIGN KEY (search_request_id) REFERENCES ct_search_requests(id) ON DELETE CASCADE
  - constraint: FOREIGN KEY (study_id) REFERENCES ct_studies(id) ON DELETE RESTRICT
  - constraint: UNIQUE (search_request_id, rank)
  - constraint: UNIQUE (search_request_id, study_id)
- `csv_exports.json` — Metadata for CSV files generated by searches (fields-only or full studies), including filesystem path, columns, and generation status for list/load operations. (19 rows; fields: ['id', 'search_request_id', 'export_type', 'filename', 'relative_path', 'columns', 'row_count', 'bytes', 'file_sha256', 'generated_at', 'status', 'error_message', 'created_at', 'updated_at'])
  - lifecycle `status`: ['pending', 'writing', 'completed', 'failed', 'deleted']
  - constraint: FOREIGN KEY (search_request_id) REFERENCES ct_search_requests(id) ON DELETE SET NULL
  - constraint: UNIQUE (relative_path)
  - constraint: CHECK (export_type IN ('fields_csv','full_studies_csv'))
  - constraint: CHECK (status IN ('pending','writing','completed','failed','deleted'))

## Business rules enforced by the tools

- search_clinical_trials_and_save_studies_to_csv must create a ct_search_requests row with search_type='expression', set max_studies from the parameter (default 10), store requested_fields from the fields parameter (nullable), and set save_csv/filename from parameters; it must populate ct_search_results up to max_studies and update results_count and status accordingly.
- get_studies_by_keyword must create a ct_search_requests row with search_type='keyword', store keyword and max_studies (default 20), and populate ct_search_results; if save_csv is true it must create a csv_exports row of export_type='fields_csv' linked to that search_request_id.
- get_full_studies_and_save must create a ct_search_requests row with search_type='expression' and must ensure ct_studies.full_payload is present (fetch and upsert if missing/stale) for each returned study; it must create a csv_exports row of export_type='full_studies_csv' and mark it completed only after file is written and checksummed.
- get_full_study_details must upsert into ct_studies by nct_id if not present; on success set cache_status='full', last_fetched_at=now, and store full_payload; on fetch failure set cache_status='error' and fetch_error.
- get_study_statistics must create a ct_search_requests row with search_type='statistics' and may compute statistics only from ct_studies cached fields and/or recent ct_search_results; if condition is provided it must filter by ct_studies.conditions containing the condition string (case-insensitive match) or by normalized condition mapping in result_payload.
- list_saved_csv_files must return only csv_exports rows where status='completed' and relative_path exists on disk; if a file is missing on disk, the implementation must transition csv_exports.status to 'deleted' (soft-delete) or 'failed' with an error message.
- load_csv_data must resolve the requested filename to exactly one csv_exports row with matching filename and status='completed'; if multiple rows share a filename, it must prefer the most recent generated_at, and it must reject path traversal (e.g., any filename containing directory separators or '..').
- FK integrity: ct_search_results rows cannot exist without a parent ct_search_requests row; deleting a search request must cascade delete its ct_search_results; csv_exports may remain with search_request_id set to null if the originating request is deleted.
- Quota/limits: max_studies must be clamped or rejected if > 1000; CSV exports must reject writing if expected rows exceed max_studies or if filename length > 255.
