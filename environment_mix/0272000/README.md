# SMART-E2B — local MCP environment

SMART-E2B stores metadata for ephemeral secure sandboxes, code execution runs (Python/JavaScript), and a per-sandbox virtual filesystem (uploaded and generated files). The main workflows are: create/locate a sandbox for a caller, execute code producing outputs and artifacts, and manage files (upload, list directories, read file contents) within a sandbox lifecycle.

Repository: https://github.com/Leghis/smart-e2b
Homepage: https://smithery.ai/server/@Leghis/smart-e2b

## Datastore

- `api_keys.json` — API credentials used by clients to access the service and to enforce quotas/rate limits across sandbox, execution, and file operations. (19 rows; fields: ['id', 'key_hash', 'key_prefix', 'label', 'status', 'quota_exec_per_day', 'quota_file_ops_per_day', 'quota_storage_bytes', 'rate_limit_rps', 'last_used_at', 'created_at', 'updated_at'])
  - lifecycle `status`: ['active', 'suspended', 'revoked']
  - constraint: unique(key_hash)
  - constraint: unique(key_prefix)
  - constraint: quota_exec_per_day >= 0
  - constraint: quota_file_ops_per_day >= 0
- `sandboxes.json` — Ephemeral secure compute environments that host code execution and a virtual filesystem for a specific API key. (18 rows; fields: ['id', 'api_key_id', 'status', 'region', 'runtime_image', 'idle_ttl_seconds', 'expires_at', 'last_activity_at', 'total_storage_bytes', 'created_at', 'updated_at'])
  - lifecycle `status`: ['provisioning', 'ready', 'busy', 'stopped', 'expired', 'error']
  - constraint: fk(api_key_id) references api_keys(id) on delete restrict
  - constraint: idle_ttl_seconds between 30 and 86400
  - constraint: total_storage_bytes >= 0
- `executions.json` — Individual code execution runs inside a sandbox for Python or JavaScript, including captured outputs and resource usage. (18 rows; fields: ['id', 'sandbox_id', 'api_key_id', 'language', 'status', 'code', 'stdin', 'stdout', 'stderr', 'exit_code', 'started_at', 'finished_at', 'timeout_seconds', 'cpu_millis', 'memory_peak_bytes', 'created_at', 'updated_at'])
  - lifecycle `status`: ['queued', 'running', 'succeeded', 'failed', 'cancelled', 'timeout']
  - constraint: fk(sandbox_id) references sandboxes(id) on delete cascade
  - constraint: fk(api_key_id) references api_keys(id) on delete restrict
  - constraint: timeout_seconds between 1 and 600
  - constraint: cpu_millis is null or cpu_millis >= 0
- `files.json` — Virtual filesystem entries (files) within a sandbox; includes uploaded content and artifacts generated by executions. (19 rows; fields: ['id', 'sandbox_id', 'created_by_execution_id', 'path', 'directory', 'name', 'content_type', 'size_bytes', 'sha256', 'storage_backend', 'content_inline_base64', 'object_store_key', 'status', 'created_at', 'updated_at'])
  - lifecycle `status`: ['active', 'deleted']
  - constraint: fk(sandbox_id) references sandboxes(id) on delete cascade
  - constraint: fk(created_by_execution_id) references executions(id) on delete set null
  - constraint: unique(sandbox_id, path) where status = 'active'
  - constraint: size_bytes >= 0
- `usage_events.json` — Append-only accounting events for enforcing daily quotas and auditing operations (execute, upload, list, read). (17 rows; fields: ['id', 'api_key_id', 'sandbox_id', 'execution_id', 'file_id', 'tool', 'status', 'request_bytes', 'response_bytes', 'error_code', 'occurred_at', 'created_at', 'updated_at'])
  - lifecycle `status`: ['accepted', 'rejected', 'succeeded', 'failed']
  - constraint: fk(api_key_id) references api_keys(id) on delete restrict
  - constraint: fk(sandbox_id) references sandboxes(id) on delete set null
  - constraint: fk(execution_id) references executions(id) on delete set null
  - constraint: fk(file_id) references files(id) on delete set null

## Business rules enforced by the tools

- Every tool call must authenticate to exactly one api_keys row with status='active'; otherwise create a usage_events row with tool=<tool>, status='rejected', error_code='invalid_api_key' or 'key_inactive'.
- executePython and executeJavaScript create an executions row with language ('python'|'javascript') and status='queued', then transition to 'running' and finally one of ('succeeded','failed','timeout','cancelled') consistent with the declared lifecycle transitions.
- execute* operations must be associated with a sandbox: if no ready sandbox exists for the api_key_id, create a new sandboxes row (status='provisioning' -> 'ready') before starting the execution; executions.sandbox_id must reference that sandbox.
- No file operation (uploadFile, listFiles, readFile) may proceed when the referenced sandbox status is in ('expired','error'); such attempts must write usage_events with status='rejected' and error_code='sandbox_unavailable'.
- uploadFile upserts files by (sandbox_id, path) only when existing status='active'; if a file exists with status='deleted', it must be recreated as a new active version by inserting a new files row or by transitioning status back to active only if policy explicitly allows (default: do not allow).
- listFiles must only return files where files.status='active' and files.directory equals the requested directory (default directory is '/'); it must not return deleted files.
- readFile must only return content for files.status='active' and within the caller's sandbox scope; if storage_backend='object_store', the service must fetch by object_store_key; if 'inline', it must decode content_inline_base64.
- Per api_key_id, enforce quota_exec_per_day by counting usage_events where tool in ('executePython','executeJavaScript') and status in ('accepted','succeeded','failed','timeout','cancelled') with occurred_at within the current UTC day; when exceeded, reject new execute* calls with error_code='quota_exec_exceeded'.
- Per api_key_id, enforce quota_file_ops_per_day by counting usage_events where tool in ('uploadFile','listFiles','readFile') and status in ('accepted','succeeded','failed') with occurred_at within the current UTC day; when exceeded, reject with error_code='quota_file_ops_exceeded'.
- Enforce quota_storage_bytes by ensuring sum(files.size_bytes) for active files across non-expired sandboxes for an api_key_id does not exceed api_keys.quota_storage_bytes after an upload; otherwise reject upload and do not create/activate the file row.
- sandboxes.last_activity_at must be updated on every accepted tool call touching that sandbox; when now - last_activity_at exceeds idle_ttl_seconds, a background job must transition the sandbox to status='expired' and prevent further operations.
- Foreign key integrity must ensure executions.api_key_id matches sandboxes.api_key_id for the referenced sandbox; if mismatched, the write must fail.
